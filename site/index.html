pyauto-xpp

XPPAUT 8.4, by Bard Ermentrout, and its AUTO, made available to Python. For batch work and Python workflows: every XPP command is a Python call, AUTO runs from scripts (also for delay equations), and models can be written in Python. For interactive exploration, XPPAUT itself remains the place to go; both share the same numerics.

Quick start #

Ways to get it: one small tool that fetches everything (uv or pixi), or pip. Nothing to install at all: open a tutorial in Google Colab.

curl -fsSL https://pixi.sh/install.sh | bash   # installs pixi, once
export PATH="$HOME/.pixi/bin:$PATH"            # use it in this terminal (new terminals have it)
git clone https://github.com/ZetaOne/pyauto-xpp && cd pyauto-xpp
pixi run lab        # JupyterLab with the tutorials opens in your browser
pixi run examples   # every worked-example notebook, one line each
pixi run test       # the package's tests
python -m pip install pyauto_xpp-0.5.0-cp312-cp312-win_amd64.whl   # the wheel for your Python, from Releases
python -m pip install matplotlib jupyterlab ipywidgets plotly anywidget jupytext
python tools/jupytext_default.py   # .py scripts open as notebooks
jupyter lab         # in the unzipped repository folder

On Windows use uv or the prebuilt wheel (Releases): building from source there needs the MinGW-w64 compiler (MSYS2), not Microsoft's.

The first run downloads Python and the packages and builds XPP's C library; after an update only what changed is downloaded again. No git? Take the .zip, unzip it and run pixi run lab in that folder.

One small program, uv, fetches Python, pyauto-xpp and the packages by itself, the same way on Linux, macOS and Windows. Nothing to download by hand: uv picks the right wheel for your computer from the wheel list.

curl -LsSf https://astral.sh/uv/install.sh | sh   # installs uv, once (open a new terminal after)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"   # installs uv, once (open a new terminal after)
uv run --find-links https://zetaone.github.io/pyauto-xpp/wheels/ --with pyauto-xpp python -c "import pyxpp; print(pyxpp.__file__)"   # check
uv run --find-links https://zetaone.github.io/pyauto-xpp/wheels/ --with pyauto-xpp --with matplotlib --with jupyterlab jupyter lab   # JupyterLab

The tutorials: take the .zip (or git clone https://github.com/ZetaOne/pyauto-xpp), unzip it, and run the JupyterLab line above in that folder.

The first run downloads everything (a minute); after that uv reuses its cache and starts in about a second. Add --python 3.12 to choose the Python version. In a project of your own: uv add pyauto-xpp --find-links https://zetaone.github.io/pyauto-xpp/wheels/.

We suggest a fresh conda environment, so pyauto-xpp and its packages stay apart from everything else. Install conda once, with either Miniconda (small: conda and Python only) or Anaconda (large: with many scientific packages). The commands are the same for both; on Windows type them in the Anaconda Prompt, on Linux and macOS in a terminal.

conda create -n pyxpp python=3.12 -y      # once: a new environment called pyxpp
conda activate pyxpp                      # every time you use it

Then download the wheel for your system and Python version from the Releases page (see Downloads below) and install it with the tutorial packages:

python -m pip install pyauto_xpp-0.5.0-cp312-cp312-<your system>.whl
python -m pip install matplotlib jupyterlab ipywidgets plotly anywidget jupytext
python -c "import pyxpp; print(pyxpp.__file__)"   # check
jupyter lab                                       # open the tutorials

cp312 is Python 3.12: pick the wheel whose tag matches python --version (cp39 to cp315). Linux x86_64 and ARM (glibc 2.28+), macOS Apple Silicon (11+) and Intel (10.9+ up to Python 3.11, 10.13+ for 3.12-3.13, 10.15+ for 3.14-3.15), Windows x86_64.

Builds XPP's C library on your computer, so it needs a C compiler (gcc or clang).

git clone https://github.com/ZetaOne/pyauto-xpp && cd pyauto-xpp
python -m pip install .            # or: pip install ".[plot]" for matplotlib too
python -m pytest -q tests          # optional: the tests (needs pytest)

A first look

import pyxpp
from pyxpp.builder import ModelBuilder

mb = (ModelBuilder("fhn")
      .ode("v", "v-v^3/3-w+i").ode("w", "eps*(v+a-b*w)")
      .parameter(i=0.2, a=0.7, b=0.8, eps=0.08).initial(v=-1.2, w=-0.6))
m = mb.load()
tr = m.run(total=200)                         # Initialconds > Go
m.equilibrium({"v": -1.2, "w": -0.6})         # Newton + eigenvalues
m.run(total=300); m.run_last()
d = m.auto.run("i", start="steady", ds=0.01, parmin=0, parmax=2)   # AUTO
d.special("HB")

Tutorials #

42 worked examples in seven notebooks, one per level, from first steps to AUTO on delay equations: each model with its equations, step-by-step explanations and checks against exact or published values. And 31 interactive notebooks with sliders and an AUTO panel. Notebooks use xpptut.py from their folder: download it with them, or take everything (.zip).

Isochrons #

An oscillator's phase, extended off its limit cycle: the isochrons are the curves of equal asymptotic phase. These notebooks start from the idea and lead to the global isochrons of the reduced Hodgkin–Huxley neuron by continuation, as in Osinga & Moehlis, SIAM J. Appl. Dyn. Syst. 9 (2010). In Google Colab the first cell installs pyauto-xpp; run it first. Locally: pixi run isochrons.

notebook·Isochrons 01

What is an isochron? FitzHugh–Nagumo, then the reduced Hodgkin–Huxley neuron

Phase on the cycle, asymptotic phase, the phase map and its contour lines, points on one isochron moving together, kicks and the phase response curve; then why the reduced HH isochrons need continuation.

One hundred FitzHugh–Nagumo isochrons by continuation

The method of Osinga & Moehlis on FitzHugh–Nagumo: each isochron as a family of orbit segments of a boundary value problem, continued in AUTO stage by stage with the concatenation; checked against the brute-force phase.
